# CAI Core Canonical Model and Branch Relationship

## 1. Purpose

This document defines the canonical conceptual relationship between the core CAI model and its derived operational branches.

Its objective is to eliminate ambiguity regarding the nature of CAI and to formally clarify how different CAI expressions relate to the same architectural foundation.

---

## 2. Canonical Principle

CAI is not a collection of unrelated models.

CAI is a single architectural family with:

- one canonical core
- multiple derived operational expressions

The canonical core defines the invariant principles of CAI.

Derived branches apply those principles to specific operational domains.

---

## 3. Canonical Core

The canonical CAI core is defined as a:

> decision-centric integrity architecture for continuous validation, traceability, admissibility control, and anti-contamination across dynamic environments

This core is characterized by:

- decision as the unit of assurance
- explicit state awareness
- continuous contextual validation
- enforcement at execution boundaries
- traceability across the lifecycle
- controlled extensibility
- protection against contamination and invalid propagation

The canonical core is therefore architectural, not jurisdiction-specific, and not limited to a single sector or operational loop.

---

## 4. Core Logical Constructs

The canonical CAI core is expressed through the following constructs:

- Decision State Awareness (DSA)
- Environmental State Awareness (ESA)
- Decision lifecycle states
- Revalidation conditions
- Enforcement boundary
- Traceability model
- Contamination control
- Runtime admissibility logic

These constructs represent the stable identity of CAI across all branches.

---

## 5. Derived Branches

Derived branches are operational expressions built on top of the canonical core.

They do not redefine the core.

They contextualize it.

### 5.1 Decision Integrity Branch

This branch applies CAI to:

- governance
- execution assurance
- cross-system validity
- runtime decision control

This branch is the one used by CAI-MX.

---

### 5.2 Operational Defense Lifecycle Branch

This branch applies CAI principles to a cyber defense lifecycle structured around operational stages such as:

- MODEL
- HARDEN
- DETECT
- ISOLATE
- DECEIVE
- EVICT
- RESTORE

This branch expresses CAI as an operational defensive workflow.

It is a derived operational profile, not the canonical definition of the CAI core.

---

## 6. Non-Contradiction Rule

The decision integrity model and the seven-stage operational lifecycle are not contradictory.

They operate at different abstraction levels.

- The canonical core defines what CAI fundamentally is
- The operational lifecycle defines how CAI may be expressed in one operational branch

Therefore:

> the operational lifecycle must be interpreted as a branch implementation profile, not as the ontological definition of CAI itself

---

## 7. Governance Rule for Future Extensions

Any future CAI branch must:

- preserve the canonical constructs
- avoid redefining CAI at the ontology level
- declare its scope, context, and operational purpose explicitly

No regional, sectoral, or runtime branch may replace the canonical core.

---

## 8. Application to CAI-MX

CAI-MX is a regional implementation branch aligned with the Decision Integrity Branch.

It inherits the canonical CAI core and applies it to:

- APF-aligned environments
- runtime decision validation
- cross-system execution control
- institutional auditability
- measurable integrity enforcement

CAI-MX does not derive from the seven-stage operational defense lifecycle as its primary identity.

Its primary lineage is:

> Canonical Core → Decision Integrity Branch → CAI-MX

---

## 9. Architectural Consequence

This relationship preserves coherence across the repository:

- CORE remains universal
- branches remain contextual
- implementations remain derived
- regional labs remain extensions, not redefinitions

This prevents conceptual fragmentation and protects the framework from taxonomic drift.

---

## 10. Conclusion

CAI has one canonical architectural identity.

Its derived branches may differ in operational emphasis, but they must remain subordinate to the same core.

This document establishes that:

- the canonical CAI model is decision-centric and integrity-based
- the seven-stage cyber defense lifecycle is a valid derived branch
- CAI-MX belongs to the decision integrity branch
- no branch may redefine the core itself
